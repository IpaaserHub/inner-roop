# inner-roop

一本の改善ループではなく、ループのグラフを自動で回す。

Peter Steinberger の "loops or graphs?" に対する Carlos E. Perez の整理が、このリポジトリの形になっている。ループは指標・参照・差分・動作の四拍子で、それだけでは次の四つで壊れる。

- グッドハート。見ている数字だけが、別の意味になる。
- 上への盲目。参照が正しいかを、ループの内側では問えない。
- 衝突。独立したループが、互いに打ち消し合う。
- 測定の腐敗。監視する側を、誰も見ていない。

グラフはそれを配線で扱う。最適化には対になる監視を付け、参照は遅いループが持ち、衝突は仲裁が持ち、測定は監査がアンカーに突合する。アンカーのないグラフは、報告書同士が確認し合う循環になり、単一ループより遅く壊れる。

## 自動で回す

```bash
node --experimental-strip-types runner/auto.ts
```

状態は `work/STATE.json`、人間が読む面は `work/STATUS.md`、経過は `work/TRACE.jsonl`。
続きから進む。場面か形を変えると、状態は最初からになる。

GitHub Actions の **auto-loop** は毎日 00:00 UTC に、接地したサポートボットのグラフを 12 tick 進めてコミットする。今すぐ回すときは Actions から `auto-loop` を手動実行する。止めたいときは、そのワークフローを無効にする。

## エージェントが読むとき

`PROTOCOL.md` が一周の契約。`work/ANCHORS.md` は凍結で、最適化のために書き換えてはいけない。
